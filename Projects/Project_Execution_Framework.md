# Project Execution Framework (6-Week Cycles)

> Ship faster by artificially constraining time and focusing relentlessly on the next action.

## 1. The Pitch (Week 0)
Before starting, define:
- **The Problem:** What are we solving?
- **The Appetite:** How much time are we willing to spend? (Max 6 weeks).
- **The Solution:** What does the finished version look like?
- **The Rabbit Holes:** What are the known risks or scope creeps to avoid?
- **No-Gos:** What are we explicitly *not* building in this cycle?

## 2. The Build (Weeks 1-6)
- **Break it down:** Slice the project into vertical, functional chunks. Do not build horizontally (e.g., all database, then all frontend). Build one complete feature slice end-to-end first.
- **Get to "Done" quickly:** Ship the ugliest, functional version of the core feature in Week 1.
- **Next Action focus:** Always know the *exact next physical action* required to move the project forward. (e.g., Not "Design database," but "Write SQL schema for user table").

## 3. The Cool-down (Weeks 7-8)
- No new feature work.
- Fix bugs, clean up technical debt, update documentation.
- Decide what to pitch for the next 6-week cycle.

## 4. Execution Rituals
- **Daily:** What is the one next action to unblock this today?
- **Weekly Check-in:** Are we on track to hit the 6-week deadline? Do we need to cut scope to hit the date? (Never extend the deadline; always cut scope).
